## Explicit CPU request, then Main-owned execution

Use C:/Users/USER/miniconda3/python.exe from the repository root, with
`examples/greenhouse_sim` on PYTHONPATH. Request creation does full CPU replay;
it never starts Kit. Both request file and future run directory must be new.

```powershell
$env:PYTHONPATH = (Resolve-Path examples/greenhouse_sim).Path
python -B -m sim_data.native_generated_reference.owner_v1 prepare-request --plan ABS_CPU_PLAN --plan-sha256 CPU_PLAN_SHA --isaac-python D:/isaac-sim-6.0.1/python.bat --native-deps D:/research/tomato-pi-policy/data/sim_data/native_capture_deps_py312_v1 --output NEW_RUN_DIR --request-output NEW_REQUEST_JSON
```

Only after Main authorizes the native slot:

```powershell
python -B -m sim_data.native_dataset.reference_bridge_owner_v1 --request ABS_REQUEST_JSON --request-sha256 REQUEST_SHA
```

The neutral entrypoint first checks its actual CIM command using the unchanged
raw `classify_process`, with no current-PID or supervisor exception. It calls
owner_v1.run in the SAME CPU process. The owner repeats this raw check before
resource admission and after worker exit. Direct `owner_v1 run` is deliberately
rejected: its module name matches the frozen guard's `native_generated` marker.
`--check-only` checks ONLY the actual raw owner classification, not request or
global resource readiness, and never starts native.

The owner invokes exactly `python.bat -m sim_data.native_generated_reference.worker_v1
--request ABS_REQUEST_JSON --request-sha256 REQUEST_SHA`. Do not invoke the worker
directly: it requires matching owner-start and owned-command declarations.
The owner holds the same fixed Windows mutex name as future serial_phases,
without importing or binding that active module. It checks the frozen process
guard, memory/commit reserve and disk reserve; the worker separately requires
the exact singleton Kit process before SimulationApp. These are scoped launch
checks, not a global exclusion guarantee against unrelated legacy launchers.

No wait queue, retries, process kills or next campaign. On an owner interruption,
the owner waits for its one child to exit before releasing ownership, then fails.
A nonzero exit, cleanup failure, remaining native process or mismatched replay
cannot publish a completed receipt. Output is create-only and failure evidence
is preserved. Use a new request/output after a failure; do not resume in place.

## Native initialization and measurements

Worker preflight is hash/strict-structure/resource only. Full check_plan can
import USD and runs in the frozen scene AFTER SimulationApp. An actual running
SimulationApp instance is required before importing/calling the scene. The
is_running API was checked in local Isaac 6.0.1 simulation_app.py and python_api.md;
the raw annotator/payload interfaces are unchanged frozen implementations.

Timings record initial/final hash preflight, SimulationApp startup, full scene
preparation, geometry/camera/framing, each of six warmup payloads, final payload,
static monitor setup, native validation/masks/metadata, labels/query trace,
raw writes and pre/post source hashing. The frozen scene preparation combines
proof replay and USD setup; this is labeled as a combined measurement, not an
invented split. Owner wall time includes bootstrap/cleanup; post-exit replay has
its own timing. No integrity-hash cache or shorter render budget is introduced.

## CPU post-exit replay / observed inventory

```powershell
python -B -m sim_data.native_generated_reference.audit_v1 --capture ABS_RUN/capture --result-sha256 RESULT_SHA
python -B -m sim_data.native_generated_reference.inventory_v1 --receipt ABS_RUN/launcher_receipt.json --receipt-sha256 RECEIPT_SHA
```

Audit reconstructs current original/generated anatomy, complete background
catalogues, world coordinates, camera/FK, full-ID masks, native Z/RGB callback
digests, visibility/quality, labels and complete traces from saved raw bytes.
It does not compute a replacement depth image. Runtime geometry screens and
past process history remain producer declarations, not offline OS attestation.
Independent replay is performed now; a pinned old receipt alone is not proof
that an earlier audit actually ran.

Inventory accepts only this exact completed owner chain, preserves captured
decisions, actual PNG byte size and admission.decoded_rgb_digest, original donor,
target/cap lineage, full-scene/lighting/actual-pose identities and source pins.
It reuses original scene accounting on the genuine authenticated original plan,
not a schema-masquerading generated plan. It reports only this explicit pair:
global inventory joins, morphology/near-image qualification and release remain
separate. Exact duplicate counts are diagnostic, not independent-context credit.

Optional observer and new JSON codec are intentionally not imported or bound.
Later production should integrate their qualified APIs through one explicitly
versioned producer boundary, not clone this collector per storage experiment.
